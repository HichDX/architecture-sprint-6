* Стратегия масштабирования и отказоустойчивости
    + Горизонтальное масштабирование для микросервисного приложения является более эффективным решением, поскольку позволяет просто добавлять новые экземпляры сервисов для обработки увеличивающегося объёма нагрузки. Это будет полезно если будет неожиданный рост пользователей.

* Конфигурация развёртывания приложения в Kubernetes
    + Я выбрал независимые кластеры, чтобы обеспечить изоляцию между регионами, что упростит управление и оптимизирует обработку трафика.

* Балансировка нагрузки
    + Будет использоваться глобальный балансировщик нагрузки, который распределяет трафик по регионам, основываясь на географическом местоположении пользователя и загруженности серверов и локальные балансировщики, которые обеспечат равномерное распределение трафика между экземплярами микросервисов внутри каждого региона.
    + Все инстансы будут проверяться с помощью health checks, чтобы убедиться, что они работают корректно. В случае недоступности одного из экземпляров, трафик будет перенаправлен на другие работающие инстансы.

* Фейловер-стратегия:
     + Active-Active фейловер, который будет поддерживать все зоны доступности в активном состоянии.

* Шардирование базы данных не требуется на текущем этапе, поскольку общий объём данных составляет 50 GB.
